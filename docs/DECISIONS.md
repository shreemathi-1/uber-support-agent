# Decision log

Numbered, with evidence where it exists. Bootstrap-phase entries are marked; numbers from that phase are plumbing checks, not results.

1. **Built the pipeline on a provisional taxonomy and 12 placeholder help articles** so evaluation tooling existed before the manual data work. `taxonomy.py` intents and `AMOUNT_LIMIT`/`AUTO_ALLOW` are guesses; articles carry `date_checked: UNVERIFIED-PLACEHOLDER`. Replaced on <date>.
2. **Cache key = SHA-256(model + json.dumps(messages, sort_keys=True))** (session 1). Sorted keys so dict ordering in a prompt builder cannot cause a spurious miss. Sampling params (temperature, max_tokens) are deliberately *not* in the key: they are fixed per stage, so the model + messages already identify the call. Revisit if a stage ever varies them.
3. **`cached_llm` takes `call_fn(model, messages)`** rather than a zero-arg closure, so the network function is a plain importable function that can be swapped for a fake in tests.
4. **`DB_PATH` env var (default `data/app.db`)**, read at call time, not import time, so tests point it at a temp file without reloading modules.
5. **Session 1 ran on Python 3.14 (`.venv`)** although the stack pins 3.11. Pinned wheels in `requirements.txt` target 3.11; the Dockerfile will use `python:3.11-slim`. Flagged, not yet resolved.
6. **Golden-set sampling unit is a customer turn, not a thread root** (session 2). No root tweet in the data replies to anything (checked: 0 of 40,886), so a literal "history if the root is a follow-up" would leave the history column empty for all rows and make `is_repeat_contact` unlabellable. Candidates are the root turn (history empty) and the second customer turn (history = root), one row per thread; follow-ups therefore appear in natural proportion. Tweet ids for follow-up turns are recovered from `uber_tweets.csv` by (created_at, clean_text); 2 ambiguous keys are skipped.
7. **Both the sampled turn and its history turn are removed from the retrieval corpus.** Rule 4 only requires the sampled id, but leaving the root of the same thread in the corpus would let retrieval hand the drafter the customer's own earlier message.
8. **Keyword buckets are coverage steering only.** `driver_side` has 128 eligible roots, so the 15-minimum is reachable; the bucket name is never written to the CSV.
9. **Scripts run as modules (`python -m scripts.x`)** so they share helpers (`is_english`) without path hacks; `scripts/__init__.py` exists for that reason.
10. **`sample_golden.py` refuses to overwrite a golden set that has any label filled in.** `make data` reruns from scratch (split → sample → validate), so without this guard a rerun after labelling would wipe hand labels. With labels present it keeps the file and only re-applies the corpus removal. Tested: one label set, rerun, file byte-identical.
11. **Deflection regex widened after eyeballing the first split** (session 2 fix). Added: following up, be in contact, in-app support/messaging/help/message, send a note, reach this link, check this link, follow the link, for more info, learn more, more information. Informative share fell from 19.5% to 13.6% (7,301 pairs). Link-only replies ("visit here: for more") count as deflection because the link text was stripped and nothing answerable remains. Golden set was not resampled; corpus removal re-applied to the same 227 rows.
12. **validation.json reports two date ranges.** All Uber-related tweets span 2014-05-27 to 2017-12-03 because hop-2 extraction pulls in older customer tweets; Uber_Support-authored tweets span 2014-12-20 to 2017-12-03; that is the range to quote in the README (stats.json's Apr 2016 start came from a different subset and should be reconciled).
13. **Fallback responses are cached under the primary model's key** (session 3). `llm.groq_chat` falls back to `FALLBACK_MODEL` after 3 failed attempts, but the cache key was computed by the caller with `PRIMARY_MODEL`. Reproduction therefore replays whatever answered, and a warning is logged when the fallback fired. Acceptable for a cache; the eval report should note how many rows fell back if it is ever more than a handful.
14. **Invalid enrich responses are cached too.** The cache stores whatever the model returned; the retry appends the validation error to the user turn, which gives a different key. A message that once produced bad JSON costs one cache hit plus one retry lookup forever after, never an extra network call. Simpler than teaching the cache about validity.
15. **Enrich prompt wording** (session 3): urgency `high` covers stranded / safety / time-critical / angry repeat contact, `medium` any unresolved problem, `low` questions and feedback. `mentions_safety` and `mentions_legal` got one-line definitions each so the flags the rules depend on are not left to the model's judgement. History turns are rendered as `Earlier (<role>): ...` lines before `Message: ...`.
16. **Switched Groq models to `openai/gpt-oss-120b` (primary) and `openai/gpt-oss-20b` (fallback)** on 2026-09-12. Groq decommissioned `llama-3.3-70b-versatile` and `llama-3.1-8b-instant` on 2026-08-16 (console.groq.com/docs/deprecations). Judge unchanged (Gemini Flash-Lite, different family). `llm.groq_chat` gained an optional `reasoning_effort` (sent via `extra_body`, since the pinned groq SDK predates the typed parameter); enrich uses `"low"` because classification needs no long chain of thought and the free tier is token-limited. `scripts/check_models.py` probes both models with one json_mode call; both parsed on first try. Any enrich cache entries keyed on the old model ids are dead weight and can be ignored.
17. **Retrieval index shape** (session 4). Chroma cosine space, embeddings supplied by us (MiniLM, normalised) so Chroma never downloads its default ONNX model. `pairs` = all 7,268 informative pairs + a seeded sample of 12,732 deflection pairs (cap 20,000; 67 MB on disk, 88 s to build). `intent` metadata on pairs is the keyword bucket mapped onto Intent values: a retrieval hint, never a label. No bucket covers `policy_or_info_question`, so that intent always takes the unfiltered fallback.
18. **Fallback thresholds.** Unfiltered requery when the intent-filtered query returns fewer than 3 pairs (or 0 help chunks) or the best hit has cosine distance above 0.6. The 0.6 is a guess to revisit with `peek_retrieval.py` output; the drafter gets distances back so it can ignore a far help chunk.
19. **`Context` narrowed to `examples` + `facts`.** Retrieval returns only what it found; `run.py` will carry message, history and enrichment separately. `RetrievedPair.source` added so the drafter can prefer informative examples over deflection templates.
20. **Bucket regexes moved to `pipeline/buckets.py`** with the short names kept as keys, because `sample_golden` sorts buckets by name and renaming them would have changed the golden sample (verified byte-identical after the move).
21. **`posthog==5.4.0` pinned.** chromadb 0.6.3 calls `posthog.capture` with the pre-6.0 signature; with posthog 7.x every client and query call logged "Failed to send telemetry event" even with `anonymized_telemetry=False`. Pinning below 6 removes the noise without touching chromadb.
